# 인천공항 데이터와 2.5D 모델

## 실제로 사용하는 공식 데이터

[인천국제공항공사 T1 주차장 혼잡도](https://www.airport.kr/ap_ko/964/subview.do)의 지상 1층·지하 1층·지하 2층 잔여 대수, 페이지가 표시하는 점유율과 마지막 갱신 시각을 사용한다. 별도 인증키가 없는 공개 HTML 페이지에서 표시된 값만 읽는다. 점유율은 페이지의 `num-line` 막대가 가진 원래 백분율이며 잔여 대수에서 전체 수용량을 역산하지 않는다.

수집 시 보존한 스냅샷은 2026-10-30 20:27:23 KST 기준이다.

| 층       | 공식 잔여 대수 | 공식 점유율 | 80면 모델 초기 주차 |
| -------- | -------------: | ----------: | ------------------: |
| 지상 1층 |            264 |         74% |                  59 |
| 지하 1층 |            126 |         75% |                  60 |
| 지하 2층 |            357 |         73% |                  58 |

이는 저장 시점의 값이다. 화면의 **공식 데이터 갱신**을 누르면 공식 페이지를 다시 확인하고 새 관측값·시각으로 실험을 초기화한다. 갱신된 브라우저 값은 고정된 파일이나 이미 수행한 평가를 자동으로 덮어쓰지 않는다.

- `public/data/incheon-t1.json`: 시연·오프라인 재현용 공식 스냅샷
- `data/sources/incheon-t1-excerpt.html`: 당시 페이지의 갱신 시각·주차 현황 발췌
- `data/sources/incheon-t1-fixture.json`: 파서 회귀 검증용 고정 기대값
- `GET /api/incheon`: Vite dev/preview에서 사용하는 서버 측 갱신 경로
- `pnpm refresh:airport`: 공식 페이지를 수집하여 저장 스냅샷 갱신

서버는 대상을 공식 URL 하나로 고정하며 최대 10초의 제한 시간, 동시 요청 병합과 60초 캐시를 사용한다. 브라우저가 공식 사이트에 직접 CORS 요청을 보내지 않는다. 공식 페이지 형식 변경·접속 실패 시 임의 수치를 생성하지 않고 기존 스냅샷을 유지하며 안내한다. 일반 정적 호스팅에는 `/api/incheon` 서버를 따로 구현해야 하며, 그 경우에도 저장 스냅샷 시연은 가능하다.

## 실제 값과 합성 가정의 경계

| 구분           | 사용 방식                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 공식 관측      | 층별 잔여 대수·점유율·갱신 시각                                                                                                                  |
| 공식 배치 참고 | [T1 공식 구역 안내도](https://www.airport.kr/Web-home/_UI/images/fnct/parkingPlaceInfo/parking-map01_ap_ko.jpg), 동일 페이지의 층별 H/A/C/D 안내 |
| 축소 모델      | 4행×20열의 80면, 중앙 구획 간격, 서·동 상대 배치                                                                                                 |
| 합성 초기 상태 | 점유율에 맞춰 고른 주차면 위치와 기존 차량의 잔여 체류시간                                                                                       |
| 합성 후속 수요 | 차량별 도착·출차 요청, 예측 오차, 차종·색상                                                                                                      |
| 시각적 구성    | 터미널·조경·조명·차체, 도로 폭·거리·주차 동작 보간                                                                                               |

구역은 터미널 쪽의 H(서)·A(동), 그 뒤의 C(서)·D(동) 상대 배치를 반영한다. 공식 층별 안내에서 지하 2층은 H/A만 표시되어 해당 모델은 2개 구역을 사용한다. **정밀 주차면 좌표·측량 도면·공항 전체 수용량을 재현한 모델은 아니다.** 실제 264대 잔여를 80면 모델의 잔여 면수처럼 표시하지 않는다.

초기 주차 수는 `round(80 × 공식 점유율 / 100)`으로 정한다. 차량 ID가 `ICN-PARKED-…`이면 시작 전부터 주차한 합성 배경 차량, `ICN-…`이면 이후 들어오는 합성 수요다. seed를 고정하면 같은 초기 면·체류·후속 수요를 재현한다.

## 엔진과 시각화

80면 모델은 긴 통로·중앙 연결 구간에 3 tick과 동시 용량 3, 짧은 구간에 1 tick과 용량 1을 사용하고 모든 간선에 1 tick 진입 간격을 둔다. 이를 통해 긴 구간에서 차량 3대가 시차를 두고 이동하도록 한다. 통로는 일방향이며 노드 대기 공간은 무제한인 거시적 단순화다. 충돌·정밀 차간거리·교차로 우선권을 푸는 미시 교통 모델은 아니다.

2.5D 화면은 Three.js의 직교 카메라를 사용하는 실제 3D 장면이다. 차체·경사진 유리·지붕·타이어·휠·전후등, 터미널과 그림자 등을 절차적으로 생성한다. 주차·출차는 엔진의 예약된 시간 구간 안에서 곡선 보간하고 방향을 부드럽게 바꾼다. 시각적 보간이 통로 비용을 새로 계산하거나 차량의 배정 결과를 바꾸지는 않는다. 주차 출발 직후의 후진·조향도 이 보간에 포함된다.

카메라 회전·확대, 위에서 보기, 초기 시점 복원과 선택 차량 따라가기를 제공한다. 큰 단일 화면과 Nearest/RL 분할 화면은 동일한 엔진 결과를 재생한다. 주야간 조명은 화면 표현만 변경한다. WebGL2가 필요하며 미지원 시 오류 안내 후 계산된 지표는 계속 표시한다.

## 지표와 학습 범위

초기 배경 차량은 주차 소요시간·출차시간·이동거리 평균과 입력 차량 수에서 제외한다. 전체 점유율·통로 혼잡·누적 지연·비용에는 포함한다. CSV의 `initial` 열과 JSON의 `initial` 필드로 구별한다. 배경 차량도 끝까지 출차시켜 비교 종료 시 비용을 잘라내지 않는다.

20면 정책을 80면 모델에 적용하지 않는다. 공항용은 403→48→80 신경망의 별도 DQN으로 250 episode 학습했다. 학습 seed 1000~1249, 검증 seed 50001~50003, 평가 seed 90001~90030을 분리한다. 저장 스냅샷의 지상 1층에서 학습하고 세 층에서 평가하며, 다른 층·갱신된 점유율에 대한 성능을 보장하지 않는다. 정책 가중치·설정·학습 로그·독립 평가 파일을 보존한다.

```bash
pnpm train:airport
pnpm evaluate:airport
pnpm start -- --scenario incheon --floor ground --strategy rl --count 180
```

`experiments/evaluation-airport.json`은 3개 층 × 4개 전략 × 30개 seed = 360회 결과, 정책·입력 해시와 관측 스냅샷을 기록한다. 같은 관측 스냅샷에 대해 수요 seed를 반복한 실험이며, 실제 수요 시계열을 30일 관측한 것이 아니다. 현재 결과에서 RL의 일반적 우수성은 확인되지 않았다.
