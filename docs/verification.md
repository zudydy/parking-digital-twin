# 구현 검증과 시연 절차

구현을 진행하면서 자동 테스트·CLI 실행과 실제 Chromium 브라우저를 확인했다. 최초 계획은 2026-10-27에 작성했으며, 아래 기록은 작업 중 수행한 검증 내용이다.

## 자동 검증

- `pnpm test`: 26개 통과.
- `pnpm build`: TypeScript 검사와 Vite 운영 빌드 통과.
- `pnpm format:check`: 전체 소스·문서 형식 검사.
- Nearest 기존 규칙·CSV 입력 검증은 중간 프로토타입 회귀 테스트로 유지한다.
- 새 엔진은 단일 차량의 시간·비용·점유율을 손계산 기대값과 비교한다.
- 동일 시각 입차의 실제 대기, 이동 중 예약, 만차, 같은 시각 공간 재사용을 확인한다.
- 세 시나리오와 기준 전략 조합에서 동일 seed 결과 일치, 차량 출차 완료, 간선 사용 구간·주차면 예약 구간의 비중복을 확인한다.
- 학습 전이 보상 합과 episode 전체 비용이 일치하며 마지막 출차 비용도 포함됨을 확인한다.
- DQN 가중치 학습에 따른 target 오차 감소, 저장·복원 추론 일치, 행동 선택 및 bootstrap target의 가용 행동 마스킹을 확인한다.

## 브라우저 검증

Playwright CLI로 로컬 앱에서 다음 동작을 확인했다.

- 공통 재생·일시정지·초기화·한 단계 진행, 끝에서 단계 버튼 비활성화.
- 타임라인 앞으로 이동 → 끝으로 이동 → 같은 시점으로 되감기 후 두 지도 DOM 상태의 완전 일치.
- 사무실·공연장·쇼핑몰 전환과 재생 초기화.
- RL·Random·Rule-based 전환, 수요 70↔110대와 예측 오차 6↔20 설정.
- 차량·주차면 선택과 양쪽 전략 상세, 선택 경로 토글.
- 결과 JSON·차량별 CSV·CSV 양식의 실제 다운로드 이벤트 및 성공 여부.
- 중복 차량 ID CSV 오류 표시, 정상 CSV 재업로드 후 오류 해제·시나리오 실행·끝까지 탐색.
- CSV 사용 중 합성 설정 잠금, 합성 시나리오 복귀 후 설정 활성화.
- 데스크톱 1440×1100, 모바일 390×844 화면 캡처 확인과 가로 넘침 검사.
- 외부 폰트 요청 없이 화면 렌더링. 정책을 불러오지 못할 때 기준 전략으로 전환하고 오류 안내.

브라우저 스크린샷은 Git에서 제외하는 `output/playwright/`에 저장한다. 일반 동작에서는 React 개발 도구 안내 외 앱 오류가 없었다. 운영 빌드에서도 정상 로딩을 확인했으며, 정책 실패 복구 점검에서 의도적으로 차단한 policy.json 요청의 네트워크 오류는 별도로 확인했다. 후속 변경이 있으면 해당 흐름을 다시 점검한다.

## 3분 시연

1. `pnpm dev`를 실행하고 공연장·70대·예측 오차 ±6·seed 42·DQN을 선택한다.
2. 시간 슬라이더를 약 25 tick으로 옮겨 배정된 구역 차이를 확인한다.
3. 차량 또는 예약 주차면을 선택하여 양쪽 정책의 배정 위치와 선택 경로를 비교한다.
4. 약 60~85 tick을 재생하여 집중 출차와 통로 대기를 관찰한다. 주황색은 실제 대기열이다.
5. 끝으로 이동해 주차·출차 시간, 누적 지연, 미배정률과 비용을 비교한다. 이 seed에서 RL이 나쁘더라도 그대로 설명한다.
6. 쇼핑몰로 전환해 분산 수요를 확인하고, `experiments/evaluation.json`에서 독립 seed 30회 평균·표준편차를 확인한다.
7. 결과 JSON 또는 CSV를 내려받는다. 보고서에는 단일 시연 seed 결과와 반복 평가를 구분해서 사용한다.

## 해석 시 주의

- 실시간 센서가 연결된 실제 시설 복제본이 아닌 합성 디지털 트윈 실험이다.
- 도로 노드의 대기 공간과 교차로 충돌은 단순화했다.
- 기본 모델의 총 경로 길이는 동일하다. 거리 최적화 효과를 주장하지 않는다.
- 주차·출차 평균은 배정 차량만 포함하므로 미배정률을 함께 설명한다.
- 단일 학습 seed 정책의 평가이다. RL의 일반적 우수성·통계적 유의성·실제 운영 효과를 주장하지 않는다.
