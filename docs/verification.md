# v0.5 검증 기록

2026-10-30 구현 검증이다. 최종보고서 본문과 구별하며, 결과의 근거·범위를 기록한다.

## 직접 탐색 추가 검증

- 첫 자리가 비면 가상 탐색 지연 없이 주차하며 전역 주차면 선택 함수를 호출하지 않는다.
- 첫 통로가 모두 차면 실제 외곽 순환 간선을 통과해 다음 통로에서 발견한다. 발견 전에는 해당 주차면을 예약하지 않는다.
- 동시 도착의 현장 공간 선점, 통로 용량·면수 입장 제한, 탐색 실패 후 실제 퇴장·비용을 검증한다.
- 탐색이 출차 예측을 바꿔도 동일하게 동작하고, 순환로 추가가 기존 안내 관찰·지표를 바꾸지 않는다.
- 주차면이 아직 없거나 탐색 후 포기한 차량의 이동 자세가 유한하고 연속적이다.
- 기본 무안내/Nearest 분할 화면, 실제 순환 사례·현장 확인 기록, 과거 시점의 주차면 미노출, 탐색 시작 방식 전환을 브라우저에서 확인했다.
- 새81조건×30교통seed×13실행31,590회와 별도 시작 방식 민감도1,080회를 보존했다.

## 자동 검증

- `pnpm test`: 45개 통과. 단일 차량 손계산, 통로·주차면 비중복, 만차·재현성, 출차까지 보상 보존, 실제 원본 시각과 준비 지연 분리, 대체 출구의 도달 가능성을 검증했다.
- 출차정보를 임의로 바꿔도 제외 정책 입력이 변하지 않는지 검사했다. DQN 가용 행동·bootstrap 마스킹, 가중치 업데이트를 확인했다.
- 공식 HTML 파서·80면 초기화·배경 비용, 이동 자세 연속성, 재생 시간 경계를 검증했다.
- 대응 bootstrap의 상수·동일 표본·서로 다른 학습/교통 축, 관측 시각 중복 제거·누락 시각을 만들지 않는 동작을 검사했다.
- `pnpm build`, `pnpm format:check` 통과.
- `pnpm research:verify`: 전체 31,590행·2,430개 동일 입력 그룹·18개 정책 해시를 검증하고, 세 환경·각 3종 시나리오/층·교통 seed 90001/90015/90030의 기본 규모·오차6 조건 351회를 독립 재실행한다. 저장한 모든 지표와 입력 해시가 일치해야 성공한다.

## 브라우저 검증

Playwright CLI로 실제 Chromium에서 확인한다. 캡처는 Git 제외 경로 `output/playwright/`에 보존한다.

- 세 환경과 출차정보 사용/제외 정책 전환, 배정 시점 탐색·후보·Q값·제외 입력 표시
- 재생·정지·시간 탐색, 차량 선택, 비대칭 출구의 실제 간선 표시
- 반복 실험 화면의 환경·수요·규모·오차 선택, 민감도 셀, 학습 곡선·대응 구간·편차
- 실험 원자료·그림·결과 JSON·차량 CSV 다운로드. 브라우저로 받은 gzip·PNG와 게시 원본의 SHA-256이 일치함을 확인했다. 새 JSON의 local-systematic-v1·기준 search·현장 확인 기록과 CSV478개 차량 행도 검사했다.
- 공항 관측 이력·층/시간 가정 선택. 수집 시작/중지 제어는 고정된 실제 관측 응답으로 검사하고, 실제 수집은 CLI8회로 확인했다. 서버 이력에 HTML이 응답되는 정적 호스팅 조건에서도 저장 관측8개로 대체됨을 확인했다.
- 데스크톱과 모바일의 가로 넘침 및 앱 오류

개발 중 서버 재시작에 따른 Vite 연결 재시도는 앱 기능 오류와 구분한다. 최종 확인은 운영 빌드에서 수행한다.

## 권장 시연 순서

1. 공항 80면에서 저장 관측 시각·공식 값과 합성 범위 안내를 보여준다.
2. 재생과 차량 추적·시점 전환으로 이동·통로 대기·주차를 확인한다.
3. 배정 의사결정을 선택해 해당 시점의 관찰·후보·Q값을 확인한다.
4. 출차정보 제외 정책으로 전환해 별도 학습 정책과 입력 마스킹을 보여준다.
5. 비대칭 환경에서 경로 8/11과 두 출구를 확인한다.
6. 실험 분석에서 31,590회, 18개 정책·3/30 seed와 대응 구간을 설명한다. 처리율을 먼저 비교하고 RL이 우수하지 않은 조건도 보여준다.
7. 수요×오차 조건과 학습 곡선을 확인하고, 공항 실제 시계열의 짧은 기간·미보정 시간 가정을 설명한다.
8. 원자료·PNG 그림·설정을 내려받아 재현 경로를 확인한다.

다운로드 검수에서 Vite의 gzip 자동 해제로 파일 확장자와 내용이 달라지는 문제를 발견했다. 압축 원본을 application/gzip 첨부로 제공하는 미들웨어를 추가하고 브라우저 다운로드 해시 일치로 재검증했다.
