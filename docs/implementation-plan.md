## 최종 완료 기준

1. 하나의 공통 엔진으로 차량의 입차 → 배정·예약 → 이동 → 주차 → 출차 대기 → 출구 이동을 처리한다.
2. 주차면 중복 배정, 이동 중 예약 해제, 차량 유실을 방지한다. 동일 시각 이벤트 순서를 명시한다.
3. Nearest / Random / Rule-based / 학습된 RL 정책을 동일 입력에서 실행한다.
4. 사무실(반복 피크), 공연장(집중 출차), 쇼핑몰(분산·불확실 수요) 3개 합성 시나리오를 제공한다.
5. 웹에서 차량 이동·경로·통로 혼잡·예상 출차·상세 정보와 시간 이동을 확인한다.
6. Nearest와 RL을 같은 시간축으로 나란히 재생하고 결과를 비교한다.
7. 학습에 쓰지 않은 seed로 반복 평가하고 결과·설정·정책을 파일로 남긴다.
8. 재실행 명령, 의미 있는 테스트, 브라우저 시연 절차가 준비되어 있다.

## 구현 순서

### 1. 공통 환경과 지표 확정 — 가장 먼저

- `Scenario`, `Layout`, `Vehicle`, `Strategy`, `SimulationResult` 계약을 분리한다.
- 기존 20면을 유지하면서 통로·입구·출구·구역을 그래프로 정의한다. 임의 레이아웃 편집기는 만들지 않는다.
- 거리와 시간 단위를 명시하고, 차량 속도·통로 처리 용량·주차 소요시간을 설정값으로 둔다.
- 이동 중에는 주차면을 예약하며, 출차 차량이 주차면을 떠난 시점에 공간을 해제한다.
- 통로 구간별 용량 제한과 FIFO 대기열로 혼잡을 계산한다. 시각화만을 위한 임의 혼잡 수치를 사용하지 않는다.
- 결정 시점에 정책이 관찰할 예상 정보와 엔진만 아는 실제 출차 요청을 구분한다.
- 기존 `duration`의 의미와 새 시나리오의 출차 요청 시각을 명시한다. 이동시간을 더하면서 체류시간 정의를 암묵적으로 바꾸지 않는다.
- 재생용 이벤트/궤적은 엔진에서 생성한다. UI에서 별도 차량 이동 규칙을 계산하지 않는다.

완료 확인: 주차면 중복 없음, 통로 용량 준수, 모든 배정 차량 출구 도달, 혼잡 시 대기 발생, 동일 seed 재현.

### 2. 기준 전략과 시나리오

- Nearest는 그래프 최단거리 기준으로 변경한다.
- Random은 seed를 받는다.
- Rule-based는 거리와 현재 통로 대기, 예상 출차 집중도를 명시적 점수로 조합한다.
- 사무실·공연장·쇼핑몰 수요 생성기를 만들고 저수요·고수요 및 출차 예측 오차를 조절한다.
- 만차 처리는 기존처럼 미배정으로 유지하고 모든 전략에 같은 규칙을 적용한다. 통로 대기와 만차 미배정을 구분한다.

완료 확인: 동일한 외부 차량 입력과 레이아웃을 모든 전략에 전달한다. 배정 이후 혼잡과 이동 결과는 각 전략의 실행에서 독립적으로 계산한다.

### 3. 강화학습 한 종류 완성

- 20개 주차면을 행동으로 선택하는 단일 에이전트 DQN을 우선 구현안으로 삼는다. 구현 환경과 작은 학습 실행을 확인한 뒤 확정한다.
- 점유·예약, 통로 대기, 현재 시각, 현재 차량의 예상 체류·출차 정보를 관찰값으로 구성한다.
- 사용 불가 주차면은 행동 마스크로 제외한다. 만차 이벤트는 선택 가능한 행동이 없는 별도 처리를 둔다.
- 보상은 이동·대기 비용을 중심으로 시작한다. 지연된 출차 비용도 episode 종료까지 반영하고, 보상 가중치를 설정으로 기록한다.
- 실제 이동을 계산하는 엔진을 학습과 평가에서 공유한다. 별도 언어를 사용하더라도 서로 다른 교통 모델을 중복 구현하지 않는다.
- 작은 환경에서 학습·정책 저장·재로드·추론을 먼저 연결한 뒤 반복 학습을 실행한다.
- 정책 파일, 상태 인코딩 버전, 보상 설정, 학습 seed, 학습 곡선을 저장한다.
- 웹 추론은 저장된 정책을 사용한다. 규칙 기반 함수를 RL로 표시하거나 추론 도중 새로 학습하지 않는다.

완료 확인: 실제 학습으로 가중치가 갱신되고 저장 정책으로 재현 가능하며, 미사용 seed 평가가 가능하다. Nearest보다 우수한 결과 자체는 완료 조건으로 두지 않는다.

### 4. 웹 시각화와 비교

- 기존 재생 제어를 공통 타임라인 컴포넌트로 분리한다.
- 도로·주차면·차량·경로·혼잡 레이어를 표시한다.
- 차량 클릭 시 도착, 예상 출차, 실제 상태, 배정면, 이동·대기 정보를 제공한다.
- Nearest와 RL의 같은 시각을 함께 재생하며 각 화면은 해당 실행의 상태를 표시한다.
- 시간별 점유·대기 그래프, 최종 지표 표와 기준 전략 대비 차이를 보여준다.
- 기존 Node 파일 읽기를 CSV 파서에서 분리하여 웹에서도 같은 입력 검증을 사용한다.
- CSV 업로드와 결과 CSV/JSON 다운로드를 추가한다.

완료 확인: 시나리오·정책 변경 시 재생 초기화, 뒤로 탐색한 상태와 최초 실행 상태 일치, 오류 입력 안내, 비교 시간축 동기화.

### 5. 평가와 마감 검증

- 3개 시나리오 × 기준 전략 및 RL × 평가 seed 30개를 목표로 배치 실행한다. 학습 실행시간 확인 후 반복 수를 조정하고 실제 사용 수를 기록한다.
- 동일 seed의 차량 입력으로 비교한다. 학습·튜닝·최종 평가 seed를 분리한다.
- 평균 주차 소요시간(도착→주차 완료), 평균 출차 소요시간(출차 요청→출구), 총 이동거리, 누적 지연, 미배정률을 수집한다.
- 점유율과 혼잡은 정의한 동일 관측 구간에서도 비교한다. 모든 차량이 빠져나갈 때까지의 배출 구간과 수요 관측 구간을 구분한다.
- 배정 차량 기준 지표와 전체 차량 기준 처리율을 함께 표시해 미배정 증가가 성능 향상처럼 보이지 않게 한다.
- 평균과 표준편차, 시나리오별 차이를 저장한다. 학습 보상 개선과 독립 평가 개선을 구분한다.
- 핵심 엔진 테스트, 타입 검사, 빌드 후 웹 업로드·재생·비교·내보내기를 직접 확인한다.

## 일정 위험과 조정 순서

- 가장 큰 위험은 화면이 아니라 교통 모델과 RL 학습이다. 화요일에 작은 학습을 실행해 기술 위험을 조기에 확인한다.
- RL 성능이 낮으면 보상·학습 로그를 확인하고 그대로 비교 평가한다. 성능을 좋아 보이게 만들기 위해 평가 데이터를 학습에 재사용하지 않는다.
- 늦어지면 차량 에셋, 복잡한 그래프 장식, 실제 장소 재현, 고급 UI부터 줄인다.
- RL, Nearest 비교, 3개 수요 시나리오, 이동·혼잡의 실제 계산, 재현 가능한 평가를 핵심으로 유지한다. 이 범위까지 지연될 경우 완료했다고 표현하지 않고 일정과 범위를 재협의한다.
- MILP/MPC, Multi-Agent, 다층·복수 출구, 레이아웃 에디터, 센서·번호판·실시간 API, 로그인·DB는 이번 필수 구현에 넣지 않는다.
